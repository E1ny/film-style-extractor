# 输出契约与复核

## 默认报告

标题可用“风格拆解”及按风格特征命名的短语，不用画中人物、品牌、地点命名。依次列模块 0–9。每段尽量包含：①像素证据；②产生的观感；③可复用的视觉指令；④区域差异；⑤若需要，明确不确定项。能被图像证明的维度可写得细，证据不足的不填或标“无法判断”。原需求材料要求每模块约 400 字；这作为**丰富图像的详尽模式目标**，不强迫每张图都凑足。

## 一键复制正向提示词

报告后单独放一段完整连续的纯文本正向提示词。它从风格锚点开始，只串联**有可见证据**的介质、光、色、镜头构图、空间、叙事语感或质感；没有证据的介质与质感直接跳过，以自然连接词连成一段。不要写“模块 1”等标题、分点、代码围栏、解释、参考图实体、未知参数声明、模型参数或负向词。可以在报告里写“窗框/城市灯/室内”来解释观察依据，但正向段必须改成“竖向暗线/远层点状暖高光/近景压暗”等关系语汇。可直接与用户的新创作主体合并；用户给出的新主体若需要出现在最终生图提示词，放在正向段首，清楚地区分其来自用户新要求而非参考图。

提示词没有固定字数上限或最低字数。按图像实际证据、用户用途和详细度偏好描述足够的可迁移特征；不为凑长度重复内容或编造细节。校验脚本位于**本 SKILL.md 所在目录下的** `scripts/check_prompt.py`；从插件根目录运行时路径是 `skills/film-style-extractor/scripts/check_prompt.py`。可选地将正向段落写入 UTF-8 文本，用 `python <脚本路径> <file>` 检查单段格式；脚本显示的汉字数仅作参考，不是验收标准。用户说“只要提示词”则直接输出该段，不添加“正向提示词：”等前缀。

完整模式优先覆盖可见证据充分的风格特征：介质与成像、光线方向和衰减、不同区域的色彩与反差、构图和透视、空间氛围、镜头叙事感与质感细节。先在内部组织要点，再写成**一个自然段**的可复制正向提示词。每项描述都应能回指画面；对证据薄弱的维度少写或标注未知。可选地用上述 `<脚本路径>` 检查提示词是否为单段纯文本，脚本显示的汉字数只作信息，不要求达到任何范围。

低证据参考图（例如只露出窄幅底图而大部分被标题覆盖）只写可明确辨认的色彩、亮度分区和几何节奏。没有清晰像素证据时，不把颗粒、雾、晕光、散景、胶片或镜头加入正向段。

## 负向约束与模型参数

默认完整交付必须在正向段后另起一段“负向提示词”，列出此风格最容易失真的五到十个点；模块 8 的分析文字不等于这段可复制的负向提示词。“精简版”只缩短各段，不省略独立负向段。不要机械堆砌互相矛盾的负向词。若用户只要正向单段提示词，则不输出负向段。

只有用户指定目标模型和版本时才附参数建议。Midjourney 与 Stable Diffusion 系列的参数和可用语法会随版本、平台、检查点改变；先查当前官方/目标平台资料，再给画幅、风格强度、采样器、CFG 等对应建议，并标注是起点值，不暗示参数能保证复刻。用户未指定模型时只写模型无关的视觉指令。

## 提交前自检

1. 是否把参考图的人物、物体、建筑、场景类别、地点、品牌、剧情或字幕写进风格段？有则剔除或转写成视觉关系；逐个检查名词，不能因为它是常见背景（如室内、窗户、街道）就漏掉。若用户明确要保留特定内容，在内容槽独立处理。缺少证据的说明与自我解释只放报告，不放正向段。
2. 是否把观感推断写成已知器材/拍摄事实，或把模糊压缩效果当成颗粒、雾或晕光？有则改成可见效果语汇，仍不确定则删去并在报告注明。
3. 光、色、构图在主体/环境、明/暗部、中心/边缘的差异是否一致？有冲突则回看图片。
4. 负向词是否排除了正向段需要的颗粒、柔焦、文字或其他特征？有则修正。
5. 多图报告的共同特征是否在每张图均可见？特别核对近景/远景、亮区/暗区的位置，不能以其中一图概括所有图，不能把区域内局部暗形扩写成“整个前景暗”之类的全局规律。若光色、对比或构图互斥且用户未选主图，写两段各自完整、可直接复制的正向提示词；不要在单段内使用“若偏向图一／或者图二”等条件句。负向约束可共用时只给一段，不可共用时分别给。
